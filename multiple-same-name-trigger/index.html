Event and timeline triggers sharing one name

Every trigger on this page is named --t. The equalizer follows one shared state, held by the trigger instance. Scroll the page on the left, press the buttons, and watch the model on the right. The Animation setting switches between a looping and a short animation, each with ranges that suit it. Each menu below it changes one part of the model.

#section-1, #section-2 { timeline-trigger: --t view() contain / cover; }

A double-click fires two clicks first. While the instance is active those clicks are ignored; from the inactive state they activate it just before the double-click deactivates it.

Try this

  1. Jump to Section 1: it becomes fully visible, so the equalizer plays.
  2. Double-click Play / Pause: it pauses, even though section 1 is still on screen.
  3. Jump to Top: section 1 leaves. The instance is already inactive, so nothing happens.
  4. Click Play / Pause, then jump to Section 2: with the default gap, section 2 is already fully in view when section 1 leaves, so it keeps playing.
  5. Jump to End: section 2 leaves too, so it pauses.
  6. Press Toggle any time: each click flips the shared state, whichever trigger set it last.
  7. Press Replay while it's playing: the entry action runs again, as the counter shows. It's play on a looping animation, so nothing visible changes.
  8. Change one menu at a time to compare:
    • Event trigger state → Own state: right after step 1, the first Toggle click does nothing. After step 5, clicking Play / Pause does nothing.
    • Timeline triggers → Each signals on its own: in step 4 it pauses as soon as section 1 leaves, although section 2 is on screen.
    • Timeline exit → Only after an entry: jump to Section 1 partly, click Play / Pause, then jump to Top. It keeps playing, because section 1 never came fully into view. With Without an entry, it pauses.
    • No exit events → Ignored while active: in step 7 the counter doesn't change.
    • Gap → out of view: in step 4 it pauses between the sections and plays again at section 2, as separate triggers would.
    • Gap → partly in view: in step 4 it keeps playing. With Timeline exit → Only after an entry, it pauses when section 1 leaves and restarts when section 2 is fully in view.
    • Gap → becoming fully in view: in step 4 nothing happens at the handover. With Timeline triggers → Each signals on its own, it pauses and restarts in the same frame, which shows in the log and the counters.
  1. Jump to Section 1: it reaches the middle of the view, so the equalizer bumps once.
  2. Jump to Section 2: on the way, section 1 leaves its range, so the instance deactivates (there's no exit action). Section 2 then activates it again, so it bumps again.
  3. Scroll a little up and back down: section 2 leaves its range and enters it again, so it bumps again. The active range is no wider than the activation range, so nothing keeps the instance active.
  4. Press Replay: the instance is already active, but Replay has no exit events, so it bumps anyway. A click on Play / Pause is ignored, because Play / Pause has exit events.
  5. Change one setting at a time to compare:
    • No exit events → Ignored while active: in step 4, Replay does nothing.
    • Timeline triggers → Each signals on its own or Timeline exit → Only after an entry: nothing changes, because the two ranges never overlap and each section's active range is its activation range.
    • Animation → Bounce: watch Entry action runs as you go from section 1 to section 2. With contain / cover, it only goes up again with Gap → out of view, so with the other gaps a bump would play only once.
